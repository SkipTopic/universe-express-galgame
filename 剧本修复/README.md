# 剧本是怎么改出来的

这里放的是同一部小说的两种形态：**原稿**和**成品脚本**，以及 AI 改稿时依据的那份规则书。

| 目录 | 内容 | 形态 |
|---|---|---|
| `剧本编辑规范.md` | AI 改稿的规则书 | 约束文档 |
| `原剧本/` | `ch01_p.md`–`ch12_p.md`，润色后的小说原稿 | 连续段落，无演出标记 |
| `新剧本/` | `ch01.txt`–`ch12.txt`，galgame 成品脚本 | 一行一步，带演出指令 |

> `新剧本/` 与仓库里的 `story/` **内容完全一致**（12 个文件 sha256 逐一相同）。保留两份是因为：`story/` 是游戏运行时读的那份，`新剧本/` 是改稿的权威源，摆在一起才能看清「原稿 → 成品」的对照关系。

---

## 一、原版长什么样

`原剧本/ch01_p.md` 开头：

```
第1章 战争结束
Subject.　Date.

轰……

随着一声巨响，天边完全被橙黄的光亮给覆盖住了，取而代之的是那令人睁不开眼的光芒。然而在这持续了几分钟的光亮之后，天完全黑了下来。随之而来的，便是那无穷的寂静。听不见任何的枪声炮声，也看不到一束束由高能枪发出的耀眼光芒。可就在几分钟前，这里还是一阵阵的炮火连天，枪声响彻云天。现在，便是一片死寂。

我紧握着手里的光枪，待上面的激光充满了之后，便将枪口对准敌人的营地，唯恐敌人再次发出进攻。然而，奇怪的是，敌人这次没有任何的动静，你甚至连一点声音都听不见。

"奇怪。"心里想着。

我们的通讯耳便收到了长官发来的消息："敌人那边投降了，战争结束了！"
```

**它的问题不在文笔，在于它没法被引擎读。**

1. **信纸抬头没清掉**——「Subject.／Date.」是当年那种信纸的印刷抬头，扫描 OCR 时一起带进来了（只有第 1 章这一处）。
2. **一个自然段一百多字**，最长的一行 159 字。屏幕上一次显示这么一坨，玩家读着会喘不上气。
3. **引语和转述混在一行**——「我们的通讯耳便收到了长官发来的消息："敌人那边投降了"」，引擎分不清哪句是旁白、哪句是角色在说话。
4. **心理活动用引号包着**——「"奇怪。"心里想着。」，看着像台词，其实是主角在心里嘀咕。
5. **插图只有一个方括号占位**——`[插图：crop189_143309_L15.jpg]`。
6. **完全没有演出信息**——谁在说、站在画面哪一边、这时该放什么音乐、要不要转场，全靠读者脑补。引擎不会脑补。

数据：**12 章 / 748 个非空行 / 26576 字 / 单行最长 159 字**。

## 二、成品长什么样

`新剧本/ch01.txt` 开头：

```
【章节】第1章 战争结束
【音乐】bgm_scan23
【背景】bg_battlefield

轰……
随着一声巨响，天边完全被橙黄的光亮给覆盖住了
取而代之的，是那令人睁不开眼的光芒
然而在这持续了几分钟的光亮之后，天完全黑了下来
随之而来的，便是那无穷的寂静
听不见任何的枪声炮声，也看不到一束束由高能枪发出的耀眼光芒
可就在几分钟前，这里还是一阵阵的炮火连天，枪声响彻云天
现在，便是一片死寂

【音乐】bgm_scan13
我紧握着手里的光枪，待上面的激光充满了之后
便将枪口对准敌人的营地，唯恐敌人再次发出进攻
然而，奇怪的是，敌人这次没有任何的动静
你甚至连一点声音都听不见
奇怪。
我们的通讯耳便收到了长官发来的消息
长官|敌人那边投降了，战争结束了！
```

规则只有三条：

- **一行 = 一次点击。** 引擎读一行，显示一行，等玩家点一下，再读下一行。
- **`角色名|台词`** 表示有人开口说话，名牌会自动弹出这个名字。没有竖线的行就是旁白，不显示名牌。
- **`【】` 开头的行是给引擎的指令**，不显示在屏幕上。

全剧 395 条指令，分布是：

| 指令 | 条数 | 作用 |
|---|---|---|
| `【立绘】` | 157 | 角色上场 / 换表情 / `无` 清场 |
| `【背景】` | 80 | 换场景 |
| `【音乐】` | 78 | 换 BGM |
| `【转场】` | 58 | 黑场过渡，同时清空立绘 |
| `【章节】` | 12 | 章节标题横条 |
| `【插图】` | 10 | 全屏 CG / 手稿扫描页 |

## 三、AI 具体改了什么

### 1. 切句：159 字 → 最长 39 字

这是改动量最大的一条。规则写在 `剧本编辑规范.md` 里：**一行不超过 40 字，按语义断**。

不是按句号机械切，是在语义停顿处断——「然而」「取而代之的」「可就在」这些转折词前面断，一句话能独立成一个画面就断。

结果：台词本体最长 **39 字**，旁白最长 **36 字**，全剧没有一行超出这个范围。

### 2. 拆引语：一行变两行

```
原：我们的通讯耳便收到了长官发来的消息："敌人那边投降了，战争结束了！"
新：我们的通讯耳便收到了长官发来的消息
    长官|敌人那边投降了，战争结束了！
```

前半句是旁白（叙述），后半句是台词（长官在说话，要弹名牌）。原来挤在一行，引擎只能二选一。

### 3. 心理活动转旁白

```
原："奇怪。"心里想着。
新：奇怪。
```

galgame 的惯例是：**不显示名牌 = 主角的内心**。所以主角的心里话不加名字、不加引号，直接当旁白念。加名字反而会让玩家以为有个叫「奇怪」的人在说话。

### 4. 补演出指令：把「脑补」变成「参数」

原稿只有一句「希朗首长正在演讲台上激烈地演讲着」，到了脚本里长这样（下面这段是真的，直接摘自 `新剧本/ch01.txt`）：

```
【转场】
【音乐】bgm_scan06
【背景】bg_hall
希朗首长正在演讲台上激烈地演讲着
坐在台下的我们纹丝不动地认真听着
【立绘】char_xilang
希朗首长|我要感谢大家，让我们在这场战役中取得了完美的正义！
希朗首长|世界需要有人去引领它
希朗首长|如果没有人去引领它，那么无论是哪个星球，最后的结局都会走向灭亡
希朗首长|因此，我，被选上了！
发言完毕，台下一阵激烈的掌声
我附和着也鼓起了掌
【插图】crop189_143309_L15.jpg
```

一段话进来，出去的是：一场黑场转场、一首 BGM、一张背景、两行旁白、一次立绘上场、四句带名牌的台词、一张全屏插图。**从哪儿切到哪儿、谁站在台上、放什么曲子、什么时候给他一个镜头，全部显式写出来。**

这些名字不能随便取——规范里给了资产清单，只能用清单里存在的背景、立绘、CG、BGM 名，写错一个引擎就找不到图（会静默失败，屏幕上只剩背景）。

### 5. 立绘调度：谁说话谁在场

- 角色开口前必须已经上场，否则会出现「画外音」——虽然也不算崩，但很怪
- 角色离场要补 `【立绘】无`，否则上一场的立绘会赖在下一场的背景上
- 情绪明显时用表情差分：`_smile` `_angry` `_sad` `_shock`
- 两个人对话可以同场，引擎自动分左右站位，说话的那个高亮、另一个压暗

### 6. 清杂质

信纸抬头「Subject.／Date.」、页边残留、原稿里混进来的排版符号，一律清掉。

## 四、总量对比

| | 原稿 | 成品 |
|---|---|---|
| 章数 | 12 | 12 |
| 行数 | 748 个非空行 | 2420 行（395 指令 + 670 台词 + 1355 旁白） |
| 字数 | 26576 字 | 字数基本不变，只是拆行 |
| 单行最长 | 159 字 | 39 字（台词）/ 36 字（旁白） |
| 演出信息 | 无 | 395 条指令 |

**字数几乎没动，行数翻了三倍多。**因为这一轮做的不是改写，是「排版」——把一篇散文重新排成能被机器逐行播放的形状。

## 五、改完还得再改

剧本不是一次成型的。定稿之后还有两轮回改：

1. **实况游玩揪出来的文案问题 11 处**——「稚孩子」改「孩子」、「7 个小孩」改「几个」、「脸肤」改「脸蛋」、「泰山般的巨影」补名词、「流石」改「流星」、「取第二」改「取第二批」……都是逐句读出来的语病。
2. **剧情补写 3 行**——第 2 章选 3 号之后原本直接跳走，读者不明白「她为什么后到」，补了一场唤醒戏（舱门解锁 / 她还在沉睡 / 出发那天送到飞船上）。

所以你现在看到的 `新剧本/`，是至少三轮之后的版本。
